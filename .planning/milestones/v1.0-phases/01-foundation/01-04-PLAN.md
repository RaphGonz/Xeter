**`xeter/services/presenter/routers/auth.py`** — registration route:

Request model (Pydantic):
```python
class RegisterRequest(BaseModel):
    tenant_name: str           # min_length=1, max_length=100
    email: str                 # valid email format
    password: str              # min_length=8
```

Response model:
```python
class RegisterResponse(BaseModel):
    tenant_id: str
    api_key: str    # plaintext key, returned once — document this in the model docstring
    message: str    # "API key shown once. Store it securely — it cannot be retrieved."
```

Route: `POST /register`

Logic:
1. Check if email already exists across all tenants — if found, return HTTP 409 Conflict with detail "Email already registered"
2. Create tenant row via `TenantRepository.create(name=tenant_name)`
3. Hash the password via `passlib CryptContext(schemes=["bcrypt"])` — same pattern as API key hashing
4. Create user row via `UserRepository.create(tenant_id=..., email=..., password_hash=...)`
5. Generate API key via `generate_api_key()` — returns (plaintext, hash)
6. Create api_key row via `ApiKeyRepository.create(tenant_id=..., key_hash=...)`
7. Return `RegisterResponse(tenant_id=str(tenant.tenant_id), api_key=plaintext, message="API key shown once...")`

Use `tenant_session` context manager for steps 3-6 (all in one transaction). Since tenant creation in step 2 doesn't have a tenant_id yet, wrap steps 3-6 in the tenant session after the tenant is created.

Note: Step 2 (create tenant) does not use tenant_session because there's no tenant_id yet — it's the bootstrap operation. Steps 3-6 all use the new tenant's UUID.

Use FastAPI dependency injection for the session: `Annotated[AsyncSession, Depends(get_session)]`.

**`xeter/scripts/seed.py`** — deterministic dev bootstrap:

```python
"""
Seed script: creates a fixed dev tenant, user, and API key for local development.
Run: python -m xeter.scripts.seed  (or: make seed)

Idempotent: if the dev tenant already exists, prints a warning and exits without error.
Dev API key: dev-api-key-local (fixed, hardcoded — consistent with .env.example)
"""
```

Logic:
1. Connect to PostgreSQL using `DATABASE_URL` from environment
2. Check if a tenant named "dev-tenant" already exists — if so, print "Seed already applied. Run `make reset` to start fresh." and exit 0
3. Create tenant: name="dev-tenant"
4. Create user: email="dev@example.com", password hashed from "dev_password_local"
5. Store API key: hash of "dev-api-key-local" using `verify_api_key`/`generate_api_key` approach — but for seed, we need to hash the FIXED key. Use `passlib.context.CryptContext(schemes=["bcrypt"]).hash("dev-api-key-local")` to get the hash and store that.
6. Run `create_spans_table()` from `shared.db.clickhouse` to ensure the ClickHouse spans table exists.
7. Print: "Seed complete. Dev API key: dev-api-key-local"

**`xeter/scripts/reset.py`** — full teardown and rebuild:

```python
"""
Reset script: drops all DB schemas and recreates them from scratch, then re-runs seed.
Run: python -m xeter.scripts.reset  (or: make reset)

WARNING: This deletes all data. Dev environment only.
"""
```

Logic:
1. Print "WARNING: This will delete all data. Ctrl+C to cancel. Proceeding in 3 seconds..."
2. Drop and recreate PostgreSQL schema:
   - Connect as superuser (use POSTGRES_URL from env, which may differ from DATABASE_URL if it has BYPASSRLS)
   - `DROP SCHEMA public CASCADE; CREATE SCHEMA public;`
   - Run `alembic upgrade head` via `subprocess.run(["alembic", "upgrade", "head"], check=True)`
3. Drop and recreate ClickHouse spans table:
   - `DROP TABLE IF EXISTS spans`
   - `CREATE TABLE IF NOT EXISTS spans ...` via `create_spans_table()`
4. Run seed.py logic
