  <files>sdk/xeter_sdk/decorator.py, xeter/tests/sdk/__init__.py, xeter/tests/sdk/test_decorator.py</files>
  <action>
Create `sdk/xeter_sdk/decorator.py` implementing the `@xeter.trace(...)` decorator. Follow the pattern from RESEARCH.md Pattern 1 exactly.

Implementation requirements:
- `trace(*, agent_name, agent_model, tool_name=None, tool_description=None, prompt_arg=None, tools_arg=None, trace_id=None, parent_span_id=None)` — all kwargs, no positional args
- Detects `async def` with `inspect.iscoroutinefunction(fn)` — wraps as `async def` or `def` accordingly
- Captures `prompt` from `kwargs[prompt_arg]` if `prompt_arg` is set, else `None`
- Captures `available_tools_ref` from `kwargs[tools_arg]` if `tools_arg` is set, else `None`
- Captures `tool_output` as the return value of the decorated function (convert to `str` if not already)
- Captures `tool_arguments` as the kwargs dict minus `prompt_arg` and `tools_arg` keys (serialised to JSON string)
- Generates `span_id` as `str(uuid.uuid4())` each invocation
- Records `time_begin` (ISO 8601) before function call, `time_end` after
- Sets `xeter.schema.version` = `"1.0"` on every span
- If `XETER_ENDPOINT` or `XETER_API_KEY` env vars are missing → silently return, no warning
- Submits via `threading.Thread(target=_send, args=(...), daemon=True).start()`
- `_send` calls `httpx.post(f"{endpoint}/v1/spans", json=span, headers={"x-api-key": api_key}, timeout=5.0)`
- On ANY exception in `_send`: `logger.warning("xeter: failed to send span: %s", exc)` — never re-raise
- Logger: `logging.getLogger("xeter_sdk")`

Span dict field names (keys sent in JSON body):
```
span_id, trace_id, parent_span_id, agent_name, agent_model,
tool_name, tool_description, tool_arguments, tool_output,
prompt, response, raw_response, available_tools_ref,
time_begin, time_end, "xeter.schema.version"
```

`response` and `raw_response` are NOT captured by the decorator (those are agent-provided fields not available at decoration time) — set to `None`. The Analyser receives them as `null`. NOTE: The Analyser Pattern in RESEARCH.md expects these fields. Document in a comment that agents needing response capture can subclass or extend — for now, they are null.

Create `xeter/tests/sdk/__init__.py` (empty file).

Create `xeter/tests/sdk/test_decorator.py` with these test cases:
1. `test_sync_function_returns_normally` — decorated sync fn returns its value unchanged
2. `test_async_function_returns_normally` — decorated async fn returns its value unchanged
3. `test_no_send_when_env_vars_missing` — no env vars set → no httpx call (mock httpx.post, assert not called)
4. `test_span_fields_sent` — mock httpx.post, set XETER_ENDPOINT + XETER_API_KEY, call decorated fn, capture sent JSON, assert all required fields present including `"xeter.schema.version": "1.0"`, `span_id` is UUID string, `time_begin` and `time_end` are ISO strings
5. `test_send_failure_does_not_raise` — mock httpx.post to raise `httpx.ConnectError`, call decorated fn, assert fn still returns normally
6. `test_prompt_arg_mapping` — set `prompt_arg="prompt"`, call fn with `prompt="hello"`, assert span JSON contains `"prompt": "hello"`
7. `test_tools_arg_mapping` — set `tools_arg="tools"`, call fn with `tools=["tool1"]`, assert span JSON contains `"available_tools_ref": ["tool1"]`
8. `test_fire_and_forget_timing` — decorated fn completes before background thread finishes (use a mock with a short sleep, assert function return is immediate)

Use `unittest.mock.patch` for httpx. Use `monkeypatch` (pytest) for env vars. The send happens in a `threading.Thread` — tests should call `threading.active_count()` or join threads via a mock to avoid race conditions. Simplest approach: patch `threading.Thread` and capture the `target` + `args`, then call `target(*args)` synchronously in the test to inspect what would be sent.
