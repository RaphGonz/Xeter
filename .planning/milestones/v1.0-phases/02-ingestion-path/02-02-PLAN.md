Create `xeter/services/analyser/auth.py`:

Implement `verify_api_key_header` as a FastAPI dependency that:
1. Reads `x-api-key` header (raise 401 if missing with `Header(...)`)
2. Opens a PostgreSQL session via `get_session` from `xeter.shared.db.session` (same pattern used in Phase 1 Presenter)
3. Queries all rows from `api_keys` table: `stmt = select(ApiKey)`, then `result = await session.execute(stmt)`, iterate `result.scalars().all()`
4. For each key record: `match = await asyncio.to_thread(verify_api_key, supplied_key, record.key_hash)` — bcrypt is CPU-bound, must NOT block event loop
5. If match found: return `str(record.tenant_id)`
6. If no match: raise `HTTPException(status_code=401, detail="Invalid or missing API key")`

Import chain: `from xeter.shared.dal.api_keys import verify_api_key`, `from xeter.shared.models import ApiKey`, `from xeter.shared.db.session import get_session`

Create `xeter/services/analyser/queue.py`:

```python
"""Redis queue operations for the Analyser.

Span IDs are pushed to the analysis queue after acceptance.
The Embedding Worker (Phase 3) consumes via BRPOP.
"""
import logging
from redis.asyncio import Redis

logger = logging.getLogger(__name__)

ANALYSIS_QUEUE_KEY = "analysis_queue"


async def enqueue_span_id(redis: Redis, span_id: str) -> None:
    """Push span_id to the Redis analysis queue.

    Uses LPUSH — worker uses BRPOP (right-pop) for FIFO order.
    Called after span is accepted into the ClickHouse batch.

    Raises: redis.RedisError if Redis is unreachable.
    Caller should handle and return 5xx to SDK on enqueue failure.
    """
    await redis.lpush(ANALYSIS_QUEUE_KEY, span_id)
    logger.debug("enqueued span %s", span_id)
```

Note on error handling: enqueue failure is treated as a hard error (raise to caller). A span that can't be enqueued won't be analysed — better to reject and let the SDK retry (no retry in SDK, so span is dropped), than to silently swallow the enqueue failure and produce an un-analysed span with no way to know.
