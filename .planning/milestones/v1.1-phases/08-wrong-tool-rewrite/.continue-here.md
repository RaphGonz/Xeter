<decisions_made>

- Per-argument grounding (from user's pseudocode) replaces NER blob matching (old approach)
- Format checks always run regardless of whether prompt has NER candidates
- Format-valid args (e.g., ISO date) skip grounding — avoids representation mismatch FP
- Noun chunks restricted to proper-noun heads (PROPN) to avoid common-noun FP
- `difflib.SequenceMatcher` chosen over adding `rapidfuzz` dependency
- Score = min(grounding_score) across all args (worst-case), not average
- Containment check takes priority over SequenceMatcher (handles long values like SQL)
</decisions_made>

<context>
The algorithm is a merge of the user's pseudocode (per-argument, type/format/grounding)
with the existing code (ARGS-01 output error patterns). Since `available_tools` has no
schema (only name + description), type checks were replaced with key-name heuristics.

The key architectural insight that emerged during implementation: format checks and
grounding checks must be decoupled — format checks catch structural invalidity
(wrong email format) while grounding checks catch semantic mismatch (right format,
wrong value). Format-valid args should NOT be grounding-checked because representation
can differ (ISO "2025-03-05" vs natural language "March 5th").

The containment fix addresses the main false positive class: long arg values (SQL
queries, long strings) that CONTAIN the relevant NER entity but score low on
SequenceMatcher because the entity is a small fraction of the total character count.
This improved precision from 0.562 → 0.607, but a ceiling appears to exist for the
current approach.

`unnecessary_tool_call` at P=0.286 with threshold already at floor (0.10) indicates
the similarity signal used for this check does not separate true positives from negatives
— no threshold adjustment can fix a bad signal.
</context>
