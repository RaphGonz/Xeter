## Tech Debt (No Blockers)

### Phase 14 — DB Foundation
1. **Stale SUMMARY frontmatters**: Plans 14-01, 14-02, 14-03 do not include `requirements-completed` in frontmatter — DB-01, DB-02, DB-03, S3-01 are satisfied but not tracked in SUMMARY source. Implementation is correct; traceability gap only.
2. **Stale comment in spans.py** (lines 9, 442): "span_scores has NO PostgreSQL RLS" — stale after migration 004. Runtime behavior is correct (explicit WHERE clause still present). Comment misleads future developers.

### Phase 15 — Secrets Hygiene
3. **generate-secrets.sh missing vars** (fixed): Was missing `S3_ENDPOINT_URL`, `INTERNAL_API_KEY`, `ENVIRONMENT`, `CORS_ALLOW_ORIGINS`. Services would crash at startup (hard-fail on `INTERNAL_API_KEY`). Fixed during audit.

### Phase 16 — Auth Hardening
4. **Dead `verify_session_token` in Diagnosticer**: `diagnosticer/main.py` lines 78-94 define a JWT-decode function that is never passed to any `Depends()`. Trust boundary is correctly enforced by `InternalApiKeyMiddleware`. The dead code requires `SECRET_KEY` to be provisioned to Diagnosticer even though it is never called at runtime. Should be removed.

### Phase 17 — GDPR Data Deletion
5. **`--confirm` output missing Redis reminder**: Completion message prints `"DELETION COMPLETE. Tenant ... data removed from ClickHouse, PostgreSQL, and S3."` — Redis is not mentioned. Dry-run prints the Redis flush procedure, but operators using `--confirm` directly won't see it. Low severity (runbook covers it), but output is technically incomplete.

### Phase 13 — Frontend Diagnosis UI (v1.2)
6. **Missing VERIFICATION.md**: Phase 13 was shipped as v1.2 without a VERIFICATION.md. SUMMARYs confirm FRONTEND-UI-01 was completed and both plans committed. Not a v1.3 blocker; should be addressed before archiving v1.2.
