# Milestone v1.5: Silent Failure Detection

**Status:** ✅ SHIPPED 2026-05-30
**Phases:** 22–28
**Total Plans:** 23

## Overview

v1.5 implements the complete B/C/D/F/G/H failure-category taxonomy from the IBM/Berkeley AI agent research, adding 18 new detection modes across span and trace analyzers. The milestone delivers: 5 deterministic span checks (OutputSchemaAnalyzer), 6 embedding/heuristic checks across SemanticSpanAnalyzer and TraceAnalyzer, 6 best-effort proxy trace checks, full calibration infrastructure for 24 flag types, and a precision improvement pass bringing mean precision to 0.947.

## Milestone Summary

**Key Decisions:**
- CTX-03 (prompt_injection) permanently removed from scope — insufficient reliable signal
- Binary flag types extended: wrong_agent_handoff, clarification_skipped, no_verification (Phase 26); information_withholding, step_repetition (Phase 28)
- history_loss P=0.5 accepted — cross-contamination with conversation_reset is architectural
- calibrate.py DEFAULT_THRESHOLDS merge fix — ensures single-type runs don't lose existing keys
- BINARY_FLAG_TYPES set in calibrate.py: 11 types get eval-only pass (no hill climb)
- deploy/docker-compose.yml WORKER_THRESHOLD_* patched for all 16 threshold-tunable types
- wrong_tool_args excluded from P/R calibration target (low-confidence by design)

**Issues Resolved:**
- Worker idle-flush gap (INFRA-01) — Phase 22
- calibrate.py full-suite timeout — per-type runs with merge logic used as equivalent (Phases 27, 28)
- spaCy en_core_web_md missing from dev environment — Phase 27
- 14 flag types below precision target — fixed in Phase 28

**Issues Deferred:**
- python-jose → PyJWT migration (AUTH-F02) — deferred to v1.6
- Refresh token revocation store (AUTH-F01) — deferred to v1.6
- rate limiting on ingestion (OPS-F01) — deferred to v1.6

**Technical Debt Incurred:**
- history_loss P=0.5 accepted — architectural limitation; improving requires disambiguation from conversation_reset
- step_repetition WRITE_MUTATE_KEYWORDS gap in no_verification — addressed in Phase 28-03
- calibrate.py full-suite run still ~15+ min (times out in CI) — per-type approach is the workaround
