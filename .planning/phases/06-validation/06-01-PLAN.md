  <action>
Create `xeter/scripts/generate_labelled_fixture.py` that generates 200+ synthetic spans and writes them to `fixtures/labelled_spans.jsonl`. Each line is a JSON object with all SpanData fields plus `label` ("flagged" or "clean") and `anomaly_type` (one of "wrong_tool", "wrong_tool_args", "no_tool", "excessive_tool", "parsing_error", "response_anomaly", or null for clean).

Distribution per user decision: ~30% flagged / ~70% clean. Cover all six anomaly types in the flagged subset.

Each span must have realistic content:
- `prompt`: natural-language instructions (e.g., "Search the web for Python documentation", "Send an email to alice@example.com")
- `tool_name`, `tool_description`: realistic tool names and descriptions
- `tool_arguments`: JSON strings with plausible arguments
- `available_tools`: list of 3-5 tool dicts with `name` and `description` fields
- `agent_model`: use "gpt-4o" for all spans (known in TOOL_CALL_REGISTRY, avoids parsing_error false positives)
- `raw_response`: valid JSON for api_structured models (gpt-4o uses api_structured transport)
- `response`: a plausible text response

For flagged spans, make the anomaly OBVIOUS so calibration has a clear signal:
- wrong_tool: prompt says "search the web" but tool_name is "execute_sql" and available_tools has "web_search" ranked higher
- wrong_tool_args: prompt says "email Alice" but tool_arguments has Bob's email
- no_tool: prompt says "call the search function" but tool_name is None
- excessive_tool: prompt is a simple greeting but a database tool was called
- parsing_error: raw_response is malformed JSON (not valid for api_structured model)
- response_anomaly: prompt asks about weather but response is about cooking recipes

For clean spans, make prompt/tool/response semantically aligned.

Create the `fixtures/` directory at project root if it does not exist.

Run the generator to produce the fixture file. The script should be deterministic (use a fixed random seed) so the fixture is reproducible.

<task type="auto">
  <name>Task 2: Calibration harness with precision/recall curve and config auto-update</name>
  <files>xeter/scripts/calibrate.py</files>
  <action>
Create `xeter/scripts/calibrate.py` that:

1. Reads `fixtures/labelled_spans.jsonl` (the committed fixture, NOT generated on-the-fly per user decision).
2. Connects to the running embedder service at `http://localhost:8002` (via `EmbedderClient`).
3. For each candidate threshold in `np.arange(0.1, 0.95, 0.02)`, instantiates `ToolCallAnalyzer(embedder, thresholds_dict)` where thresholds_dict scales the six threshold keys relative to the sweep value (use the ratios from the existing defaults: wrong_tool=1.0x, wrong_tool_args=0.8x, no_tool=1.2x, excessive_tool=0.6x, parsing_error=1.0x, response_anomaly=0.8x).
4. For each span in the fixture, calls `analyzer.analyze(span_data)` and `analyzer.flush_scores()`. Compares predicted (any flag returned) vs actual (label == "flagged") to count TP, FP, FN.
5. Computes precision and recall at each threshold point.
6. Selects the threshold where precision >= 0.80 (user decision: optimize for precision, minimum 80% target) with maximum recall. If no threshold achieves 80% precision, selects the highest-precision point and warns.
7. Produces a precision/recall curve PNG using matplotlib: plot recalls on x-axis, precisions on y-axis, mark the 80% precision target line in red dashed, annotate the selected threshold point. Save to `fixtures/precision_recall_curve.png`.
8. Auto-updates `deploy/docker-compose.yml` by regex-patching all six `WORKER_THRESHOLD_*` lines with the calibrated values. Uses the same ratio scaling as step 3.
9. Prints a summary to stdout: selected threshold, precision, recall, and the six calibrated values.

Add `matplotlib` to `xeter/pyproject.toml` dependencies if not already present.

Handle the case where the embedder is unreachable: catch `httpx.ConnectError` at startup, print a clear error message ("Embedder not reachable at http://localhost:8002 -- run 'docker compose up embedder' first"), and exit with code 1.

Build SpanData from fixture rows using the helper pattern from the research (see interfaces above). Set tenant_id to "calibration-tenant", trace_id to "calibration-trace".

IMPORTANT: The `_check_parsing_error` method in ToolCallAnalyzer uses `TOOL_CALL_REGISTRY` and `FORMAT_GROUPS` from `tool_call_registry`. Ensure fixture spans use `agent_model: "gpt-4o"` which is in the registry, so parsing_error spans must have intentionally malformed raw_response to trigger the flag.

IMPORTANT: Exclude `wrong_tool_args` flags from the precision/recall computation per Pitfall 5 in the research (low_confidence by design). Document this exclusion in the script output.
