Rewrite `deploy/docker-compose.yml`. Make every change listed below. Read the current file first before editing.

RULES:
- Use `${VAR}` with NO fallback (`:-`) for ALL secrets. Docker Compose will fail loudly at startup if a var is unset.
- Exception: Non-secret config vars (DIAGNOSTICER_PROVIDER, DIAGNOSTICER_MODEL, ANTHROPIC_API_KEY, OPENAI_API_KEY) may keep their `${VAR:-default}` form since they are not secrets that could cause security failures.
- Wrap connection URL values in double quotes in YAML to avoid parse issues with special characters (`@`, `:`, `//`).

CHANGES TO MAKE:

**Infrastructure: postgres service**
- `POSTGRES_PASSWORD: xeter_dev_password` → `POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}`

**Infrastructure: clickhouse service**
- `CLICKHOUSE_PASSWORD: xeter_dev_password` → `CLICKHOUSE_PASSWORD: ${CLICKHOUSE_PASSWORD}`

**Infrastructure: redis service**
Add `command: redis-server --requirepass ${REDIS_PASSWORD}` to the redis service.
Add `environment:` section: `REDIS_PASSWORD: ${REDIS_PASSWORD}` (needed for healthcheck).

**Infrastructure: minio service**
- `MINIO_ROOT_PASSWORD: xeter_dev_password` → `MINIO_ROOT_PASSWORD: ${MINIO_ROOT_PASSWORD}`
- `MINIO_ROOT_USER: xeter` → keep as-is (not a secret) OR wire from `${MINIO_ROOT_USER}` — wire it from env for consistency.

**Infrastructure: minio-init service**
Replace the command entirely:

```yaml
environment:
  MINIO_ROOT_USER: ${MINIO_ROOT_USER}

   && mc mb local/xeter-payloads --ignore-existing
   && mc anonymous set none local/xeter-payloads"
```
NOTE: OPS-03 requirement text explicitly checks that `${MINIO_ROOT_PASSWORD}` appears in the mc alias command (not a hardcoded literal).
