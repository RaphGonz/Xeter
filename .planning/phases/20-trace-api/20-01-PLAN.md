**GET /traces implementation:**

Query steps:
1. ClickHouse query: get all distinct trace_ids for the tenant, with aggregated span_count, min(time_begin) as start_time, (max(time_end) - min(time_begin)) as duration in seconds. Use `toUnixTimestamp64Milli` for arithmetic or compute in Python. Query:
   ```sql
   SELECT
       trace_id,
       count() AS span_count,
       min(time_begin) AS start_time,
       dateDiff('millisecond', min(time_begin), max(time_end)) / 1000.0 AS duration
   FROM spans
   WHERE tenant_id = %(tenant_id)s
   GROUP BY trace_id
   ORDER BY start_time DESC
   LIMIT %(limit)s
   OFFSET %(offset)s
   ```
   Run via `await asyncio.to_thread(ch_client.query, ...)`.

2. Separately, count total distinct traces:
   ```sql
   SELECT count(DISTINCT trace_id) FROM spans WHERE tenant_id = %(tenant_id)s
   ```
   Run via `await asyncio.to_thread(...)`.

   Run both ClickHouse queries concurrently via `asyncio.gather`.

3. If no trace_ids returned, return immediately: `TraceListResponse(traces=[], total=0, limit=limit, offset=offset)`.

4. PostgreSQL: query flag counts per trace_id. Use a raw `text()` query (not ORM) because grouping by trace_id is cleaner with SQL aggregation. Include explicit `tenant_id` filter (RLS + belt-and-suspenders). Filter `span_id IS NULL OR span_id IS NOT NULL` — count ALL flags per trace regardless of span_id:
   ```sql
   SELECT trace_id, count(*) AS flag_count
   FROM flags
   WHERE tenant_id = :tenant_id
     AND trace_id = ANY(:trace_ids)
   GROUP BY trace_id
   ```

5. Merge: build `flag_count_by_trace` dict, construct `TraceListItem` for each CH row.

6. Return `TraceListResponse`.

**GET /traces/{trace_id} implementation:**

Query steps:
1. ClickHouse: fetch all spans for `(tenant_id, trace_id)`. Uses the MergeTree primary key efficiently (leading columns match). Sort by `time_begin ASC`:
   ```sql
   SELECT span_id, parent_span_id, tool_name, agent_model,
          time_begin, time_end
   FROM spans
   WHERE tenant_id = %(tenant_id)s AND trace_id = %(trace_id)s
   ORDER BY time_begin ASC
   ```
   Run via `await asyncio.to_thread(...)`.

2. If ClickHouse returns zero rows: return 404 stealth (do NOT return 403 — user decision).
   ```python
   raise HTTPException(
       status_code=404,
       detail={"error": "not_found", "message": "Trace not found", "status": 404},
   )
   ```
   Note: ClickHouse `WHERE tenant_id = X AND trace_id = Y` means cross-tenant lookups return no rows — identical to not-found. This is the stealth 404 per user decision.

3. No-spans-yet case: trace_id exists in PostgreSQL flags but not in ClickHouse — per user decision, return 200 with `spans: []`. However since we check ClickHouse first, "no ClickHouse rows" triggers 404. If a trace exists only in flags (no spans yet), the caller gets a 404 — this is acceptable per the agreed contract (trace existence is defined by having spans).

4. Collect `span_ids` from ClickHouse result.

5. PostgreSQL (sequential on same session — AsyncSession is NOT safe for concurrent execute calls):
   a. Query all flags for this trace_id and tenant_id:
      ```python
      await session.execute(
          select(Flag).where(
              Flag.tenant_id == tenant_id,
              Flag.trace_id == trace_id,
          )
      )
      ```
      This returns both trace-level flags (span_id=None) and span-level flags.

   b. Query span_scores for all span_ids in this trace (RLS + explicit WHERE):
      ```python
      await session.execute(
          text("SELECT span_id, analyzer_name, metric_name, score "
               "FROM span_scores "
               "WHERE tenant_id = :tid AND span_id = ANY(:span_ids)"),
          {"tid": tenant_id, "span_ids": list(span_ids)},
      )
      ```

6. Separate trace-level flags (span_id is None) from span-level flags. Build indexes:
   - `trace_flags`: [Flag] where flag.span_id is None
   - `flags_by_span`: dict[span_id -> [Flag]]
   - `scores_by_span`: dict[span_id -> [ScoreItem]]

7. Compute trace start_time (min time_begin from ClickHouse rows) and duration.

8. Assemble `TraceDetailResponse`:
   - `trace`: TraceObject with trace-level flags only
   - `spans`: flat list of SpanInTrace in time_begin ASC order (already sorted from CH query), each with their flags and scores

9. `input_tokens` and `output_tokens` are not in the current ClickHouse schema — set to `None` for all spans (the field is reserved for future schema additions).
