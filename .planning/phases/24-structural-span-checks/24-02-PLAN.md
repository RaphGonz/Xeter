<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| span.expected_output_schema → jsonschema.Draft7Validator | Untrusted JSON string from ClickHouse; must be parsed safely and rejected on malformed input |
| span.tool_arguments → jsonschema validator | Same trust boundary as above |
| span.raw_response → json.loads | Provider API JSON dump; structure varies (OpenAI vs Anthropic vs others) and may be malformed |
| span.prompt → tiktoken.encode | Arbitrary user prompt text; tiktoken encode is safe for any UTF-8 string |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-04 | Denial of Service | jsonschema validator on malformed schema string | mitigate | json.loads wrapped in try/except (JSONDecodeError, ValueError); on parse failure return [] without calling Draft7Validator — prevents SchemaError crash. Verified by test_schema_02_does_not_fire_on_malformed_schema_json |
| T-24-05 | Denial of Service | json.loads on adversarial raw_response | mitigate | _parse_finish_reason wraps json.loads in try/except; returns None on failure; _check_output_truncated tolerates None and falls through to delimiter heuristic. Verified by test_schema_03_does_not_fire_on_malformed_raw_response |
| T-24-06 | Denial of Service | tiktoken.encode on extremely long prompt (memory amplification) | accept | tiktoken encodes byte-pair tokens at ~3.5 chars/token average; a 1 GB prompt produces ~280M tokens; worker memory budget assumes prompt strings are already bounded upstream (S3 fetch in span_fetcher applies size limits). Phase 24 does not introduce a new attack surface — prompts are already loaded into memory before any analyzer runs |
| T-24-07 | Tampering | finish_reason injection via raw_response manipulation | mitigate | finish_reason is parsed from raw_response which is provider-generated, not user-generated; an attacker who controls raw_response already controls the trace data upstream. The check is best-effort and only adds a flag (no destructive action). Accept the risk; downstream consumers treat finish_reason==length as a heuristic signal, not a security event |
| T-24-08 | Information Disclosure | Flag.detail contains schema validation error messages | accept | jsonschema error messages include schema and instance values; this is acceptable because the flag is written to span_scores in the same tenant boundary as the span itself — no cross-tenant leak |
| T-24-09 | Denial of Service | Adversarial token count crafted to evade context_overflow | accept | An attacker who controls the prompt can submit token counts just under threshold; this is the calibration risk D-03 acknowledges, not a security flaw. Threshold is configurable per WORKER_THRESHOLD_CONTEXT_OVERFLOW env var (plan 24-03) and tuned via calibrate.py |
| T-24-SC | Tampering | npm/pip/cargo installs | n/a | No package installs in this plan; all deps (jsonschema 4.26.0, tiktoken 0.12.0) installed in Phase 23 |
</threat_model>
