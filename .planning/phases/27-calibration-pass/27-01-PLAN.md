The current evaluate_flag_type() processes each fixture row as a single-span list when the analyzer is a BaseTraceAnalyzer instance. This means trace-level checks that require 2+ spans (step_repetition, stale_context, etc.) will never fire — every trace has exactly 1 span. Fix this by adding a grouped-trace evaluation path.

Changes to calibrate.py:

1. Add a TRACE_LEVEL_TYPES constant — a frozenset of the flag types whose evaluation requires multi-span grouping:
   TRACE_LEVEL_TYPES: frozenset[str] = frozenset({
       "stale_context", "step_repetition", "termination_loop",
       "context_propagation_failure", "history_loss", "wrong_agent_handoff",
       "information_withholding", "conversation_reset",
       "no_verification", "incomplete_verification",
   })
   Note: "clarification_skipped" is NOT in this set — it is a syntactic single-span check.
   Note: "missing_details" is NOT in this set — it is a SemanticSpanAnalyzer (span-level) check.

2. Add a helper function group_spans_by_trace(spans: list[dict]) -> list[list[dict]] that:
   - Groups fixture rows by trace_id
   - Within each group, sorts by span_id ascending (to preserve insertion order of multi-span traces)
   - Returns a list of groups; single-span rows with unique trace_ids form single-element groups
   - Preserves all rows (no filtering)

3. Modify evaluate_flag_type() to use grouped evaluation when the emitted_flag_type is in TRACE_LEVEL_TYPES:
   - Call group_spans_by_trace(spans) to get groups
   - For each group: the LAST row in the group carries the label (actual = emitted_flag_type in last_row's anomaly_types)
   - Build SpanData objects for all rows in the group
   - Pass the full list to analyzer.analyze(span_list)
   - Count TP/FP/FN based on the group-level label vs the group-level predicted flag
   - Call analyzer.flush_scores() after each group (scores are group-level)
   - For non-TRACE_LEVEL_TYPES, behavior is unchanged (existing per-row loop)

In evaluate_flag_type(), when flag_type == "wrong_agent_handoff", instantiate TraceAnalyzer with routing_graph={"orchestrator":["search_agent","data_agent"],"billing_agent":["payment_agent"]} as a hardcoded calibration default. This matches the routing graph embedded in the fixture rows (see Task 1). Document this as CALIBRATION_ROUTING_GRAPH at module level.
