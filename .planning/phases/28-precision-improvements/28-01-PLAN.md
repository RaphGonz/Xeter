  <action>
Apply six targeted fixes. Each is isolated to its own method — do not change other methods while working through these:

**_check_context_propagation_failure() — D-09:**
Currently flags on ANY single pair (i, i-1) where the hybrid score drops below threshold. Fix: require the drop to be sustained across 2 consecutive pairs. Specifically, instead of flagging immediately when `score < threshold`, accumulate flagging candidates and only emit a Flag for span i when BOTH pair (i-1, i-2) and pair (i, i-1) scored below threshold. Implement this with a `low_score_streak` counter: initialise to 0 before the loop; increment when `score < threshold`, reset to 0 otherwise; emit a Flag only when `low_score_streak >= 2`. The log_score call still fires on every pair regardless (D-04 invariant unchanged).

**_check_history_loss() — D-12:**
The existing guard `if len(spans) < 3` ensures at least 3 spans. This is already correct per the code comment "need at least 2 prior prompts for a meaningful centroid per D-08". No change needed to the minimum span count gate — the guard already implements it. HOWEVER: raise the loop start index from `range(2, len(spans))` to `range(3, len(spans))` so that the first comparison only fires when there are at least 3 prior prompts (not just 2). This tightens the condition without breaking the existing guard.

**_check_wrong_agent_handoff() — D-10:**
The existing `if not self._routing_graph: return []` guard already handles empty/None graphs. The real problem is that during calibration, the CALIBRATION_ROUTING_GRAPH in calibrate.py is injected but some fixture traces may have agent_name values not in the graph, causing them to be treated as violations. The fix: change the flag condition from `(src not in self._routing_graph) or (dst not in self._routing_graph[src])` to `src in self._routing_graph and dst not in self._routing_graph[src]`. This means "only flag when the source IS a known agent but the destination is not permitted" — unknown source agents (e.g., clean spans with None or unregistered agent_name) are silently skipped rather than flagged. Also add a guard: if `src is None or dst is None`, continue to next pair without logging.

**_check_information_withholding() — D-13:**
Currently fires when `score < threshold` with ANY non-empty produced NE set. Add two additional preconditions before logging: (1) only fire when `len(produced) >= 2` (prior span had at least 2 NEs — single-NE responses are too noisy); (2) only fire when `score < 0.5` (more than 50% of entities withheld) — the threshold will be re-calibrated in Plan 28-03. Move the `if not produced: continue` guard to ALSO check `if len(produced) < 2: continue` (skip log_score on under-populated NE sets). The `score < 0.5` early exit (before log_score) acts as a hard precondition: if score >= 0.5, skip log_score and return [] for this pair. After log_score, the calibrated threshold still controls the final flag decision.

**_check_conversation_reset() — D-16:**
Add two tightening conditions: (1) only evaluate spans where `i >= 4` (require at least 4 spans total in the trace before flagging — more data stabilises the centroid); change `range(2, len(spans))` to `range(4, len(spans))`. (2) After computing the current score, also compute the score for the immediately preceding span (i-1) vs its prior centroid; flag only when the current score is at least 0.15 LOWER than the preceding span's score (abrupt single-step drop, not gradual drift). Store the previous step's score in a loop variable `prev_score` and initialise it to 1.0; update it each iteration. The `if score < threshold AND (prev_score - score) >= 0.15` condition replaces the single `if score < threshold` comparison.

**_check_no_verification() — D-08:**
Currently fires on any trace with tool calls but no verification keyword. Add a precondition: only flag when the trace contains at least one "write" or "mutate" tool call. Define write/mutate keywords as a local frozenset: `{"write", "create", "update", "delete", "insert", "save", "post", "put", "patch", "modify", "set"}`. Before the `has_verification` scan loop, add a check `has_write_mutate = any(kw in (span.tool_name or "").lower() or kw in (span.tool_description or "").lower() for span in spans for kw in WRITE_MUTATE_KEYWORDS)`. If `not has_write_mutate`, return [] (no log_score — this is a guard exit per D-04 invariant: guard exits do not log_score). Only proceed to the keyword scan and potential flag when write/mutate evidence exists.
