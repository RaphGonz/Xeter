**_check_response_anomaly() — D-15:**
The calibrated threshold of 0.1 means almost any prompt/response pair can fall below it (cosine similarity of 0.1 is very low). The true anomaly signal is when a response is SEMANTICALLY UNRELATED to the prompt — for example, a code response to a natural language question. Fix: add an additional precondition before the flag decision: only flag when `span.prompt` has at least 10 tokens (using simple whitespace split: `len(span.prompt.split()) >= 10`). Short prompts (fewer than 10 words) legitimately produce low cosine similarity with any response and are a major FP source. Add `if len(span.prompt.split()) < 10: return []` immediately after the log_score call (guard after logging preserves D-04 invariant — log_score fires, but then we return [] for the short-prompt case).

Wait — D-04 invariant says guard exits do NOT call log_score. But here we want to still contribute to the calibration signal for short prompts. The correct pattern: log_score always fires, then the short-prompt condition returns [] (this is NOT a guard exit, it is a post-logging conditional return). The distinction: guard exits before log_score return without logging; conditional returns after log_score do log. This approach is correct — keep log_score before the new `if len(span.prompt.split()) < 10: return []`.
