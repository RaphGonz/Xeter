<objective>
Extract the inline prompt f-string from `context_assembly.py:_format_context()` into a dedicated, co-located `prompt.md` template file. Read that file once at module import time into a module-level constant and substitute span data into it via `str.format_map()`.

This satisfies DIAG-01: the prompt becomes a human-editable file rather than a string buried in Python source, while the assembled-context behavior is byte-for-byte equivalent to the current f-string output.

Purpose: Make the prompt maintainable and reviewable as a semantic diff, and establish the substitution mechanism that Plan 02 will rewrite the content into.
Output: `prompt.md` (template), modified `context_assembly.py` (import-time read + format_map), and a new `test_context_assembly.py` (substitution + FileNotFoundError + content-presence coverage).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| disk → diagnosticer process | prompt.md is read from a trusted, version-controlled path co-located with the source; not user-supplied |
| span data → LLM API | span fields (tool_arguments, prompt_text, response_text) can contain arbitrary user-agent content, interpolated into the prompt and sent to an external LLM |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-01 | Tampering | prompt.md on disk | accept | File is version-controlled and read from Path(__file__).parent (immune to cwd); tampering requires repo/filesystem write access already equivalent to source compromise |
| T-30-02 | Information Disclosure | span data interpolated into LLM message | accept | Unchanged behavior from the existing f-string; no new injection surface introduced by extraction (per RESEARCH Security Domain). Out of scope to add LLM-input sanitization here |
| T-30-03 | Denial of Service | FileNotFoundError at import if prompt.md absent | mitigate | Correct fail-fast: service refuses to start rather than running with a missing prompt. Covered by test_missing_prompt_file_raises |
| T-30-SC | Tampering | npm/pip/cargo installs | mitigate | No packages installed this phase (stdlib only — pathlib, str.format_map). No legitimacy gate required |
</threat_model>
